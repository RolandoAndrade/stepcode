## Decisions worth remembering

- `Para` increments the counter, then yields the loop-line pause, then tests: `inspect()` at
  that pause point already shows the incremented value (fixed during Task 6's review, before
  Task 7 could assert frames against the wrong order).
- `continue()` issued from `ready` honours a breakpoint on the first statement of main; the
  "never re-stops on the statement it resumes from" rule applies only to a statement the run
  had already paused on, not to the very first step of a fresh run. `step()` from `ready`
  still just executes the first statement.
- The core is synchronous: input is a step result (`StepResult` kind `input`), not an
  `io.read` callback, so no promise lives below `runProgram` and a Web Worker or a test drives
  a run with no `await` inside the evaluator.
- User calls go through the controller as a `call` event, not through nested `yield*`: no JS
  recursion per StepCode call, so `stackDepth` (E4005, default 1000) is a policy limit rather
  than a JS stack limit, and the controller always knows the frame depth for `stepOver` and
  `stepOut`.
- The two documented v1 divergences: `Redondear(-1.5)` rounds half away from zero and gives
  `-2` (v1's JS `Math.round` gave `-1`); `valid-triangle-and-type`'s invalid-triangle case
  reads `iguales` unassigned in v1 (which silently printed nothing for it) and correctly
  raises E4003 in v2, so that one input set is excluded from the sidecar rather than forced to
  a `done` outcome.
- `Azar` (`random`) takes zero arguments and returns a `Real` in `[0, 1)`, matching
  `BUILTIN_SIGNATURES` — the brief's `random(n)` form does not exist in the signature table.
- `Redondear` (`round`) is half away from zero: `Math.sign(x) * Math.round(Math.abs(x))`.
- `Subcadena` (`substring`) yields `""` with no bounds check when `ini > fin`, because the
  corpus relies on that empty-range rule (`Subcadena(s, 1, i - 1)` with `i = 1`, and the
  symmetric case at the end of a string); otherwise both positions are bounds-checked.
- The Node loader hook exists because the corpus scripts need to run from a clean checkout
  with plain Node against this codebase's extensionless relative imports; it is committed
  rather than left as an ad hoc step so `extract-runs.ts` and `record-run.ts` stay runnable.
- `pnpm --filter stepcode test` is broken when run from the package directory (vitest finds
  the root projects glob instead); use `pnpm vitest run --project stepcode` from the repo
  root for the whole package, or with a path for one file.

## Next: sub-project 4 (editor shell)

- The worker protocol in umbrella §4.6 maps onto `Run`: the editor drives `step` / `stepOver`
  / `stepOut` / `continue` / `input` / `setBreakpoints` / `inspect` across a Web Worker
  boundary; every command is synchronous and returns a `StepResult`, so the protocol is a
  thin RPC wrapper with no promise semantics of its own inside the core.
- What the editor needs from `StepResult`: `paused.line` and `paused.frames` (innermost first,
  `Scope.order` variable order) drive the gutter and variables panel; `input.target` (name,
  static type, or `null` for `Esperar Tecla`) and `input.rejected` (an E4004 diagnostic) drive
  the input prompt and its re-ask; `wait.millis` drives a visible pause; `error.diagnostic`
  plus `error.frames` drive the error surface, and `inspect()` keeps returning those frames
  once the run is over.
- `sleep` and `budget` on `RunProgramOptions` are the fake-timer hooks: tests (and any editor
  code that wants determinism) pass a no-op or synchronous `sleep`, and a small `budget`
  forces frequent yields to the event loop for a responsive UI during a long-running program.
- The E3009 cosmetic edge the previous handoff flagged (`Escribir f()` on an array-returning
  function reporting an empty name) is fixed: `nameOf` now takes a `profile` parameter and
  names a `Call` after its callee and a `BuiltinCall` after its first spelling.
- Records and files are explicitly out of 2.0 scope (spec §1 non-goals); the interpreter does
  not model them.
